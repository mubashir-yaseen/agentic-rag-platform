# Technical Architecture & System Overview: Multimodal Agentic RAG Platform

## 1. Executive Summary

### Application Purpose & Intended Users
The application is a **Multimodal Agentic Retrieval-Augmented Generation (RAG) Platform** with Model Context Protocol (MCP) tool interoperability. It is designed for analysts, researchers, and enterprise users who need to:
- Ingest and query dense multimodal PDF documents (extracting body prose, structured markdown tables, and embedded images/charts).
- Interact across three distinct operational modes: **Multi-Document Knowledge Base**, **Company Research**, and **General Q&A**.
- Dynamically route queries between dense vector search, lexical matching, arithmetic calculation, live web search, and structured spreadsheet generation (**Excel `.xlsx` export**).

## 2. Actual Architecture

The system operates primarily in a decoupled **Client-Server architecture** (FastAPI backend + Streamlit frontend), while retaining an in-process local fallback inside Streamlit if the FastAPI backend is offline.

```mermaid

        Router & Responder -->|LLM Inference| OpenRouter["OpenRouter / OpenAI API"]
```

## 4. Frontend and Backend

### Frameworks & Local Execution
- **Frontend**: Streamlit. Started via `streamlit run ui/app.py` (or `streamlit run app.py`). Runs by default on port `8501`.
- **Backend**: FastAPI running on Uvicorn. Started via `python -m uvicorn rag_platform.api.main:app --port 8000 --reload`. Runs by default on port `8000`.

### Communication Mechanism
- Streamlit communicates with FastAPI via **HTTP REST** (`requests.post`, `requests.get`) and **Server-Sent Events (SSE)** streaming:
  - Base URL defaults to `http://localhost:8000/api/v1` (configurable via `API_BASE_URL`).
  - Chat responses stream token-by-token using SSE (`_sse_generator` in `v1.py` and `resp.iter_lines()` in `ui/app.py`).
  - Excel files generated during chat are downloaded by the user directly through the backend endpoint `GET /api/v1/files/{file_id}`.
- **Do both services need to run simultaneously?**
  - **Yes, for full functionality**: Running both ensures fast SSE streaming, proper Excel downloads, and complete agent orchestration.
  - **Partial Fallback**: If the FastAPI server is unreachable, `ui/app.py` has an internal fallback calling `RAGSystem` and `SupabaseVectorStore` directly in-process. However, the fallback does *not* support Company Research mode or Excel file downloads.

### CORS & Networking Requirements
- FastAPI configures [`CORSMiddleware`](file:///d:/projects/RAG_Github/RAG_chatbot_claude/rag_project/src/rag_platform/api/main.py#L36-L43) allowing all origins (`allow_origins=["*"]`) and exposes `X-Correlation-ID`.
- In Docker, `docker-compose.yml` configures network connectivity where the UI container accesses the API container at `http://api:8000/api/v1`.

### Exact Startup Order & Shutdown Commands
1. **Startup Order**:
   - Terminal 1 (Backend): Start FastAPI first so the embedding model prewarms and health checks pass.
   - Terminal 2 (Frontend): Start Streamlit second so it immediately detects the active backend.
2. **Shutdown**: Press `Ctrl + C` in each PowerShell terminal.

## 5. End-to-End RAG and Agent Workflow

From the moment a user submits a query, execution follows a 10-step lifecycle:

```
[User Query]
     │
     ▼
[Step 1: Request Validation & Mode Scoping]
  - Mode = "Q&A": allow_retrieval=False, doc_filters=None (strict isolation)
  - Mode = "Research": requires company_id
  - Mode = "Knowledge Base": scopes to doc_id and content_type (text/table/image)
     │
     ▼
[Step 2: LangGraph Agent Invocation] run_agent() in graph.py
     │
     ▼
[Step 3: Router Node Classification]
  - If allow_retrieval is False -> forces "direct"
  - If company_id present -> bypasses router to "retrieve"
  - Otherwise -> LLM classification + regex heuristics -> (retrieve | tool | mcp | hybrid | direct)
     │
     ▼
[Step 4: Conditional Node Routing]
  ├───────────────────────┬───────────────────────────┐
  │                       │                           │
  ▼ ("retrieve"/"hybrid") ▼ ("tool"/"mcp")            ▼ ("direct")
[Step 5: Retriever Node]  [Step 7: Tool Caller]       [Step 8: Responder]
  - Dense vector search     - Calculator (AST)          - Synthesize direct
  - Lexical candidate pool  - Web search (DDG)            general knowledge
  - TOC penalty & Prose     - Create Excel (openpyxl)     answer
  - Adjacent chunk expand   - Read file (MCP)
  - If hybrid: proceeds to Tool Caller Node
     │
     ▼
[Step 8: Responder Node (Synthesis)]
  - System prompt enforces strict grounding ("evidence-first")
  - Injects retrieved context blocks and tool outputs
  - Detects and strips unwanted tool markup (<tool_call>)
  - Emits citations and sources
     │
     ▼
[Step 9: Artifact Delivery & Metadata Packaging]
  - Packages AgentResult with reasoning_path, sources, tool_outputs
  - If Excel was created, includes file_id token in tool_outputs["generated_file"]
     │
     ▼
[Step 10: Client Presentation]
  - Streamlit displays answer, expandable sources, and an interactive "Download file.xlsx" button
```

### Flow Differences Across the Three UI Modes

| Dimension | Multi-Document Knowledge Base | Company Research Mode | General Q&A Mode |
| :--- | :--- | :--- | :--- |
| **Selection Scope** | Specific `doc_id` or global search | Specific `company_id` selected from database | No document or company scope permitted |
| **Content Filtering** | Supports `text`, `table`, `image`, or `all` | Global across all documents for that company | Disabled |
| **Retrieval Allowed** | Yes | Yes | **No** (`allow_retrieval=False`) |
| **Router Behavior** | LLM classifies query | **Bypasses router**, forces `retrieve` | **Forced to `direct`** |
| **Zero-Doc Behavior** | Standard empty search message | Hard guardrail: returns exact notice without hallucinating | N/A |
| **System Prompt** | Evidence-first grounding | Authoritative company identity enforcement | General-purpose assistant (no internal citations) |

## 6. Database and Document Ingestion

### Supported File Types & Processing Pipeline
- **File Type**: PDF (`.pdf`) only.
- **Pipeline Coordinator**: [`ingest_pdf()`](file:///d:/projects/RAG_Github/RAG_chatbot_claude/rag_project/src/rag_platform/ingestion/pipeline.py#L18-L169).
  1. Opens document via PyMuPDF (`fitz`).
  2. Iterates pages:
     - **Text**: Extracted via `extract_page_text_chunks`. If fewer than 40 characters are present, OCR fallback (`is_scanned_page`) triggers using `pytesseract` or `easyocr`.
     - **Tables**: Extracted via `extract_tables_from_page` and converted into Markdown tables (`content_type="table"`).
     - **Images**: Extracted via `extract_images_from_page`, filtered by size (>100x100px), saved locally, and tagged (`content_type="image"`). *Note*: `caption_llm=False` is set during API and UI uploads to eliminate vision LLM latency.
  3. **Chunking**: `RecursiveCharacterTextSplitter` chunks prose (default: chunk size 1000 characters, overlap 200 characters).
  4. **Embedding**: `all-MiniLM-L6-v2` produces 384-dimensional dense vectors.

### Supabase Vector Store & Database Schema
Defined in [001_create_documents_and_chunks.sql](file:///d:/projects/RAG_Github/RAG_chatbot_claude/rag_project/src/rag_platform/vectorstore/migrations/001_create_documents_and_chunks.sql):
1. **Extension**: `CREATE EXTENSION IF NOT EXISTS vector;`
2. **`documents` Table**:
   - `doc_id` (TEXT, PK): Unique document identifier.
   - `filename` (TEXT): Display name.
   - `uploaded_at` (TIMESTAMPTZ): Upload timestamp.
   - `doc_type` (TEXT): Defaults to `pdf`.
   - `metadata` (JSONB): Contains page counts, table counts, image counts, and optional `company_id`.
3. **`chunks` Table**:
   - `chunk_id` (TEXT, PK): Unique chunk ID (`<doc_id>_chunk_<idx>`).
   - `doc_id` (TEXT, FK): References `documents(doc_id) ON DELETE CASCADE`.
   - `content` (TEXT): Text content or Markdown table.
   - `embedding` (`vector(384)`): Dense embedding vector with HNSW index (`vector_cosine_ops`, `m=16`, `ef_construction=64`).
   - `metadata` (JSONB): Stores `page_number`, `content_type` (`text`/`table`/`image`), and chunk index.
4. **RPC Function (`match_chunks`)**:
   - Accepts `query_embedding`, `filter_doc_id`, `filter_content_type`, `filter_start_date`, `filter_end_date`, and `match_count`.
   - Returns chunks ranked by cosine similarity `1 - (c.embedding <=> query_embedding)`.
5. **Additional Schema Requirement**:
   - The UI and `upload_company_report.py` query a `companies` table (`id`, `symbol`, `name`) for Company Research Mode, and store PDFs in a Supabase Storage bucket named `annual-reports`.

### Key Known Risks & Caveats

1. **Unpopulated Local Environment**:
   - Running any command now will fail with `ModuleNotFoundError` until `pip install -e ".[dev]"` is run.
2. **Database Schema Dependencies**:
   - [001_create_documents_and_chunks.sql](file:///d:/projects/RAG_Github/RAG_chatbot_claude/rag_project/src/rag_platform/vectorstore/migrations/001_create_documents_and_chunks.sql) creates `documents`, `chunks`, and `match_chunks`.
   - **Risk**: Company Research Mode queries a `companies` table, which is *not* created in `001_create_documents_and_chunks.sql`. If that table does not exist in the connected Supabase instance, clicking "Research Mode" will display a UI warning.
3. **PyTorch Windows Directory Watcher Gotcha**:
   - Streamlit on Windows frequently encounters `torch.classes.__path__ = []` watcher exceptions. This is handled defensively at line 11 of [ui/app.py](file:///d:/projects/RAG_Github/RAG_chatbot_claude/rag_project/ui/app.py#L10-L11), but must be kept in place.
4. **External LLM Free-Tier Rate Limits**:
   - The default model in `.env` is `inclusionai/ling-3.0-flash-fin:free` or `nvidia/nemotron-3-ultra-550b-a55b:free`. Free-tier endpoints on OpenRouter occasionally throttle or return HTTP 429/503 during peak usage. The fallback logic in `default_llm_completion` handles this, but response latency can fluctuate.
5. **Streamlit Community Cloud Deployment Incompatibility**:
   - Streamlit Community Cloud is single-process and ephemeral. It is **not recommended** to deploy this full architecture directly to Streamlit Cloud unless backed by an externally hosted FastAPI container (e.g., Render, Railway, AWS ECS). Without the FastAPI backend, Excel generation and Company Research mode do not function.
